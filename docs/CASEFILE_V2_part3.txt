## 4. c6/c7 플래그 교체 계획과 스포일러 위험

현재 새 스크립트는 `c6.on`을 **어디서도 켜지 않는다**(코드 검색 결과 설정 지점 없음). 그래서 이 플래그를 조건으로 하는 옛 6·7장 기능은 닿지 않는다. 단, `!has("c6.on")`는 항상 참이라 지금의 새 기능(시계탑 4개 조사, 기록관 5개 오브젝트)이 이 게이트에 **의존해 작동 중**이다. 그래서 단순 삭제는 위험하다.

| 플래그                                                | 사용 위치 (참조 수)                                                         | 현재                                              | 교체 계획                                                                                                                                    | 스포일러 위험                                      |
|-------------------------------------------------------|-----------------------------------------------------------------------------|---------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------|
| c6.on                                                 | 상호작용 20, 사건 파일 UI 6, 연출/저장 6, 추리 판정 2, 새 대사 2, 옛 대사 1 | 켜지지 않음. 부정형(!c6.on)이 새 기능을 켬        | **의미 분리**: ① 새 기능 게이트 「!c6.on」은 「항상 켜짐」 상수로 치환 ② 옛 기능 게이트는 비활성 표시. Phase 1에서는 건드리지 않고 UI만 숨김 | 중간. 잘못 켜지면 옛 증거가 새 스토리에서 노출된다 |
| c6.turn                                               | 사건 파일 UI 4, 연출/저장 4, 추리 판정 2, 상호작용 1, 옛 대사 1             | 옛 대사 사슬이 켬 (도달 불가)                     | 새 사건 파일에서 참조 제거. 「그린 진술 이후」 같은 새 진행 조건은 챕터별 조건 승인 후 신설                                                  | 높음. 책임 보드 열이 이 조건으로 열렸다            |

### 단계

1.  **Phase 1 (승인 시)**: 플래그 변경 없음. 증거 메타데이터 추가, 자동 노트 표시 숨김, 인물 데이터 구조 도입.
2.  **플래그 교체 전 승인 자료**: 챕터별 공개 조건 표(어느 장에서 무엇이 열리는가)를 Loki 확인 → 승인 후 Phase 2.
3.  Phase 2 이후는 별도 승인.

## 5. 기존 저장 데이터 호환성 테스트 계획

저장 키 `bgb2.bellvillage.proto.v2`의 `S.ev`, `S.notes`, `S.flags`를 변경·삭제하지 않는다. 새 필드는 읽기 전용 파생값으로만 계산한다.

| \#  | 저장 픽스처                                                           | 확인 항목               | 합격 기준                                                |
|-----|-----------------------------------------------------------------------|-------------------------|----------------------------------------------------------|
| S1  | 새 게임 직후 (프롤로그)                                               | 4개 탭 열기             | 오류 없음, 그린 칸 없음                                  |
| S2  | 1장 중간 (니니, 토미 대화 일부)                                       | 인물·증거 탭 렌더       | 진술이 인물 카드에, 증거 탭에 진술 없음                  |
| S3  | 2장 진행 (시계 4개 조사 완료)                                         | Q2 열림, 시계 묶음 카드 | 회중시계 개별 선택 가능, 메이 소견 단서 없음             |
| S4  | 3장 퀴즈 중 (c3.qz)                                                   | 질문 5, 6               | 기존 퀴즈 흐름 변화 없음                                 |
| S5  | 4·5장 회상 중 저장                                                    | 이어하기                | 회상 재시작 마이그레이션 유지                            |
| S6  | 6장 마지막 선택 직전 (연출 점프 66)                                   | 질문 7, 타임라인        | 11:46~11:55 미표시                                       |
| S7  | 엔딩 A, B 이후                                                        | 결과 노트               | 저장 데이터 보존                                         |
| S8  | 옛 버전 저장: 옛 증거 ID(hatch, boots, record 등)와 옛 노트 80줄 포함 | 불러오기, 증거·노트 탭  | 오류 없음, 옛 ID는 비활성 표시, `S.notes` 배열 길이 불변 |
| S9  | 깨진 저장 (알 수 없는 증거 ID, 비어 있는 flags)                       | 불러오기                | 무시하고 계속, 콘솔 오류 0                               |
| S10 | 언어 전환(KO/EN) 상태                                                 | 모든 탭                 | 양쪽 텍스트 존재                                         |

- **방법**: Playwright로 localStorage에 픽스처 JSON을 주입하고 페이지 로드, 탭 4개와 서브뷰를 순회하며 콘솔 오류, `S.ev` 길이, `S.notes` 길이, 저장 후 재로드 동일성을 검사.
- **자동 점검**: 지급 대사 도달 가능성도 같은 방식으로 스크립트화해 1번 표의 「도달 가능」 판정을 플레이로 검증한다(현재는 코드 읽기 기준).
- **롤백**: 표시 메타데이터만 추가하므로 되돌려도 저장이 깨지지 않는다.
