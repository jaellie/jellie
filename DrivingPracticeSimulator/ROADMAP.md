# Real Road & Traffic Upgrade: Review and Plan

## Phase A: review of the existing project (Milestone 1)

What exists: the vehicle physics prototype (Rigidbody + WheelCollider, P/R/N/D, creep, ±720°
steering), keyboard input through `VehicleInputRouter`, a chase/top-down follow camera, a
procedural test ground and dev diagnostics. Nothing has yet been compiled or run in Unity.

| # | Finding | Impact | Action |
|---|---------|--------|--------|
| A1 | **No touch steering or pedals exist in the Unity project.** PUBG-style drag steering only exists in the browser preview. Unity input is keyboard-only. | The brief assumes a mobile control system to preserve. | Kept the input architecture unchanged. Camera look uses dedicated buttons/keys (never a drag), and on-screen buttons are uGUI, so a future `TouchSteeringController` can ignore pointers that start over UI (`EventSystem.IsPointerOverGameObject(pointerId)`). Touch steering and pedals still need to be built (Milestone 3). |
| A2 | `VehicleFollowCamera` read the V key itself. There was no camera owner. | Adding a cockpit view would mean two components fighting over the camera. | **Fixed in Phase B:** new `CameraController` owns the view mode. The follow camera is only enabled for chase/top-down. |
| A3 | No project layers or tags (no generated `TagManager`). | Can't hide the cockpit from cameras with culling masks. | The interior is switched on/off with the view mode, which also saves draw calls. Add proper layers when `ProjectSettings` exists in the repo. |
| A4 | `TextMesh` (legacy `GUI/Text Shader`) draws on top of geometry. | Dashboard text would show through the car body in the chase view. | Interior hidden outside the cockpit view. Move instruments to TextMeshPro when the UI milestone adds a Korean font. |
| A5 | Scenes are generated by code (`DrivingSim → Create Physics Test Scene`). | Re-running the menu overwrites manual scene edits. | Fine for prototyping. The city scenes in Phases C/E should be authored once as prefabs plus a road-network asset. |
| A6 | No Korean UI font asset. Text relies on OS font fallback. | Korean labels may show as boxes on some devices. | Add Noto Sans KR (SIL OFL) + TextMeshPro in the UI milestone. |
| A7 | Milestone 1 is still unverified (never compiled). | Every later phase builds on it. | **Compile and run the M1 tests first.** Report the first error. |
| A8 | No turn-signal input yet. | Phase F needs turn-signal usage checks. | Add `TurnSignal` to `DrivingInputFrame` + vehicle state before Phase F. |

## Plan for later phases (not started)

- **C: one intersection.** Road-network data (`RoadNetwork` ScriptableObject): road segments with
  lane count/width (3.0–3.5 m urban lanes), right-hand traffic, curb radii sized for the car's
  ≈6 m outer turning radius. Mesh generation for asphalt, lane paint (white dashed lane lines,
  yellow center line, stop lines, 횡단보도), curbs and sidewalks. One signalized 4-way intersection.
- **D: three AI cars.** Lane graph (lanes → connectors through intersections) generated from the
  road network. Kinematic AI on splines (no WheelColliders), with IDM-style car-following,
  smooth braking at stop lines on red/amber, and a signal phase controller.
- **E: small network.** Several intersections, side streets, narrow roads, parked cars, signs and
  speed limits (Korean urban defaults: 50 km/h arterials, 30 km/h school zones), 5–10 AI cars
  with distance-based LOD (cull or freeze far vehicles).
- **F: evaluation.** Red-light, stop-line, lane-departure, speed-limit, collision and turn-signal
  checks using the same lane graph. Penalties are filtered when the AI caused the event.
