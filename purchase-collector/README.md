# 🫐 Blueberry: 단톡방 링크 자동 정리 봇

카카오톡 단체방이나 디스코드 채널에 흩어져 올라온 링크를 모아서 정리해 주는 도구입니다. 두 가지 일을 합니다.

| 모드 | 하는 일 | 결과 |
|---|---|---|
| 🛒 **구매요청** (기본) | 다과 · 행사 물품 쇼핑몰 링크를 모아 수량 · 중복 정리 | 단가만 입력하면 되는 **엑셀 구매요청 집계표** |
| 🎬 **릴스** | 릴스 · 쇼츠 · 틱톡 링크를 직접 단 `#태그`별로 정리 | 디스코드 **메시지** (엑셀 없음) |

| 플랫폼 | 입력 방식 | 이유 |
|---|---|---|
| 카카오톡 | 사람이 "대화 내보내기"한 파일 | 공식 API가 없어서, 계정 정지 위험이 없는 공식 내보내기 기능만 사용 |
| 디스코드 | 봇(Blueberry)이 채널을 직접 읽고 결과 파일을 다시 올림 | 공식 Bot API가 있어서 자동화 가능 |

## 1. 문제: 학사조교 시절 실제로 겪은 일

학과 간담회나 행사를 준비할 때, 필요한 다과와 물품은 참석자들이 각자 단톡방에 쇼핑몰 링크를 올리는 방식으로 받았습니다.

```
[이하늘] https://www.coupang.com/vp/products/...
[이하늘] 종이컵 2박스요
[박서준] 생수 이걸로 부탁드려요 https://smartstore.naver.com/...
[최유진] 저도 종이컵 필요해요 https://m.coupang.com/vp/products/... 1박스
[이하늘] (아까 그 종이컵 다시 올려요) https://www.coupang.com/...&utm_source=share
```

이걸 정리하는 건 제 몫이었습니다.

- 대화를 처음부터 스크롤하며 링크를 하나씩 찾기
- 링크 바로 다음에 따로 보낸 "2박스요" 같은 수량을 짝지어 적기
- 같은 상품인데 PC 링크·모바일 링크·공유 링크로 모양이 달라서 중복인지 일일이 확인하기
- 엑셀에 옮겨 적고 금액 합계를 내서 예산과 비교하기

요청이 수십 건이면 시간이 오래 걸렸고, **빠뜨리거나 두 번 주문할 위험**이 늘 있었습니다.

## 2. 해결

```
카카오톡 "대화 내보내기" (.txt / .csv)      디스코드 채널 (Bot API)
                    └──────────┬──────────┘
① 메시지 읽기     카톡: PC · Android · iPhone · Mac 형식 자동 인식 / 디스코드: 봇·시스템 메시지 제외
② 기간 거르기     --since / --until (이번 행사 기간만)
③ 링크 추출       쇼핑몰 링크와 그 외 링크(설문, 공지) 구분
④ 수량·메모 연결  링크 직후 같은 사람이 3분 안에 덧붙인 말까지 한 요청으로 묶기
⑤ 중복 합치기     추적 파라미터(utm, q, rank 등)와 m./www. 차이를 지워서 같은 상품 판별
        ↓
엑셀 집계표 (단가만 입력 → 금액·합계 자동 계산)
        ↓
⑥ (디스코드) 결과 파일을 채널에 올리고, 올라간 것까지 확인
```

두 플랫폼은 **읽는 부분만 다르고** 링크 추출 · 중복 합치기 · 엑셀 생성은 같은 코드를 씁니다.

**실행 결과 예시** (가상 샘플 대화, `--mask-names` 사용)

| 번호 | 요청일시 | 요청자 | 쇼핑몰 | 요청 내용 | 수량 | 비고 |
|---|---|---|---|---|---|---|
| 1 | 2026-09-30 10:15 | 이*늘 | 쿠팡 | 종이컵 2박스요 / 저도 종이컵 필요해요 1박스 | 3 | 같은 상품 2명 요청: 이*늘(2개), 최*진(1개) |
| 2 | 2026-09-30 11:40 | 박*준 | 네이버 스마트스토어 | 생수 이걸로 부탁드려요 | | |
| 3 | 2026-10-01 15:12 | 정*호 | 11번가 | 현수막은 여기서 주문하면 될 것 같아요 1장이면 됩니다 | 1 | |

- 링크 4개가 3건으로 정리됐습니다. 같은 종이컵의 PC 링크, 모바일 링크, 재공유 링크가 한 줄로 합쳐지고 수량은 더해졌습니다.
- 설문 링크(`forms.gle`)는 구매 요청이 아니므로 **"기타 링크"** 시트로 따로 빠집니다.

**엑셀 파일 구성** ([샘플 파일](docs/sample_구매요청.xlsx))

| 시트 | 내용 |
|---|---|
| 구매요청 | 위 표 + 단가(노란 칸, 직접 입력) · 금액(자동) · 합계(자동) · 처리상태(대기/구매완료/보류/제외 선택) · 링크 클릭 가능 |
| 요약 | 읽은 메시지 수, 요청 건수, 중복 합친 건수, 예상 총액, 요청자별·쇼핑몰별 건수 |
| 기타 링크 | 쇼핑몰이 아닌 링크. 놓친 요청이 없는지 사람이 훑어보는 용도 |

## 3. 설계에서 고민한 점

**① 플랫폼이 공식으로 허용하는 방법만 쓴다.**
카카오톡을 원격 조작하는 비공식 자동화 도구는 쓰지 않았습니다. 카카오톡은 **공식 기능인 "대화 내보내기"** 파일만 읽고, 결과를 카톡으로 자동 전송하지도 않습니다. 자동 수집과 결과 전송은 **공식 Bot API**가 있는 디스코드에서만 합니다.

**② 보냈다고 믿지 않고 확인한다.**
디스코드로 결과 파일을 올린 뒤, 응답에 첨부파일이 실제로 들어 있는지 확인합니다. 확인이 안 되면 실패로 처리합니다.

**③ 개인정보는 필요한 곳 밖으로 나가지 않는다.**
대화 내용은 외부 서버나 AI로 보내지 않고 내 컴퓨터에서만 처리합니다. 디스코드도 원래 그 채널에 있던 사람들에게만 결과를 올립니다. 결과 파일을 공유할 때는 `--mask-names` 옵션으로 이름을 `김*수`처럼 가릴 수 있습니다.

**④ AI 없이 규칙으로 처리한다.**
링크 추출, 수량 인식, 중복 판별은 모두 규칙 기반이라 결과가 매번 같고, 왜 그렇게 나왔는지 설명할 수 있습니다. 회계 처리와 연결되는 업무라서 이 점이 중요하다고 판단했습니다.

**⑤ 최종 판단은 사람이 한다.**
자동화는 "모으고 정리하는 일"까지만 합니다. 실제로 살지(처리상태)와 단가 확인은 담당자가 엑셀에서 직접 합니다. 애매한 링크는 버리지 않고 "기타 링크" 시트에 남겨서 사람이 확인하게 했습니다.

## 4. 사용 방법

### ① 카카오톡에서 대화 내보내기
- **PC**: 채팅방 → 메뉴(≡) → 대화 내용 → **대화 내보내기** → .txt 저장
- **모바일**: 채팅방 → 메뉴(≡) → 설정(⚙) → **대화 내용 내보내기** → 텍스트만 보내기

### ② 실행
Python 3.11 이상이 필요합니다.

```bash
pip install openpyxl     # 엑셀 서식용 (없으면 CSV로 저장)
cd purchase-collector

# 기본: <대화파일>_구매요청.xlsx 생성
python -m purchase_collector 카카오톡대화.txt

# 이번 행사 기간만, 파일 이름 지정
python -m purchase_collector 카카오톡대화.txt --since 2026-09-28 --until 2026-10-03 -o 10월간담회_구매요청.xlsx

# 공유용: 이름 가리기
python -m purchase_collector 카카오톡대화.txt --mask-names
```

| 옵션 | 설명 |
|---|---|
| `--since`, `--until` | 기간 지정 (YYYY-MM-DD, 당일 포함) |
| `-o` | 결과 파일 이름 (.xlsx 또는 .csv) |
| `--mask-names` | 이름 마스킹 |
| `--all-links` | 쇼핑몰이 아닌 링크도 구매 요청으로 포함 |
| `--discord 채널ID` | 카톡 파일 대신 디스코드 채널 읽기 |
| `--post` | (디스코드) 결과 엑셀을 채널에 올리기 |
| `--last-days N` | 최근 N일만 집계 (오늘 포함) |
| `--only-if-new H` | (디스코드) 최근 H시간 안에 새 요청이 없으면 올리지 않음 |
| `--mode reels` | 릴스 · 쇼츠 링크를 #태그별 메시지로 정리 |

### ③ 디스코드에서 쓰기

**봇 만들기 (처음 한 번, 약 10분)**
1. [Discord Developer Portal](https://discord.com/developers/applications) → **New Application** → 이름 `Blueberry`
2. 왼쪽 **Bot** 메뉴
   - **Reset Token**으로 토큰 복사 (비밀번호처럼 관리, 절대 공유 금지)
   - **Message Content Intent** 켜기 (안 켜면 메시지 본문을 읽지 못함)
3. 왼쪽 **OAuth2 → URL Generator**
   - Scopes: `bot`
   - Bot Permissions: `View Channels`, `Read Message History`, `Send Messages`, `Attach Files`
   - 생성된 링크로 들어가서 서버에 초대
4. 디스코드 설정 → 고급 → **개발자 모드** 켜기 → `#구매요청` 채널 우클릭 → **채널 ID 복사**

**실행**
```bash
# Windows (명령 프롬프트)
set DISCORD_BOT_TOKEN=복사한토큰
# macOS / Linux
export DISCORD_BOT_TOKEN=복사한토큰

# 채널을 읽어서 엑셀 만들기
python -m purchase_collector --discord 채널ID --since 2026-09-28

# 엑셀을 같은 채널에 올리기까지
python -m purchase_collector --discord 채널ID --since 2026-09-28 --post
```

### ③-2 디스코드: 매일 자동 실행 (Python 설치 불필요)

GitHub Actions가 **매일 밤 9시쯤** 알아서 실행합니다 (무료). 구매요청 채널과 릴스 채널을 각각 처리합니다.

**구매요청 채널**
- 엑셀에는 **최근 7일** 동안 올라온 구매 요청이 모두 들어갑니다.
- **지난 24시간 동안 새 요청이 없으면 올리지 않습니다.** 같은 파일이 매일 쌓이지 않게 하려는 것입니다.
- 실패하면 채널에 "⚠️ 실패" 메시지와 실행 기록 링크를 남깁니다.

**릴스 채널** (아래 "③-3" 참고)
- 지난번 정리 메시지 이후 올라온 영상 링크만 `#태그`별로 정리해서 메시지로 보냅니다.
- 새 링크가 없으면 보내지 않습니다.

**설정 (처음 한 번)**
1. 저장소 → **Settings → Secrets and variables → Actions**
   - **Secrets** 탭 → New repository secret → 이름 `DISCORD_BOT_TOKEN`, 값은 봇 토큰
   - **Variables** 탭 → New repository variable (쓰는 채널만 등록하면 됨)
     - `BLUEBERRY_PURCHASE_CHANNEL_ID`: `#구매요청` 채널 ID
     - `BLUEBERRY_REELS_CHANNEL_ID`: `#릴스모음` 채널 ID
2. 끝. 다음 날 밤부터 자동으로 돌아갑니다.

**바로 한 번 돌려 보고 싶을 때:** **Actions** 탭 → 왼쪽 **Blueberry** → **Run workflow** → `mode`에서 purchase(구매요청) 또는 reels(릴스) 선택. 구매요청은 날짜를 직접 지정할 수 있고, 새 요청이 없어도 올립니다.

**끄고 싶을 때 (행사가 끝났을 때):** Actions 탭 → Blueberry → 오른쪽 위 **⋯ → Disable workflow**. 다시 켤 때는 같은 곳에서 Enable.

**시간을 바꾸고 싶을 때:** `.github/workflows/blueberry.yml`의 `cron: "57 11 * * *"`를 고칩니다. GitHub은 UTC 기준이라 **한국 시간에서 9시간을 뺀** 값을 씁니다 (예: 아침 8시 30분 → `30 23 * * *`).

참고
- GitHub 사정으로 실행이 몇 분~수십 분 늦어질 수 있습니다.
- 저장소에 60일 동안 아무 변경이 없으면 GitHub이 자동 실행을 멈춥니다. 멈추기 전에 이메일로 알려주고, Enable을 누르면 다시 켜집니다.

### ③-3 디스코드: 릴스 · 쇼츠 모음 정리

`#릴스모음` 같은 채널에 영상 링크를 올려 두면, 매일 밤 Blueberry가 **새로 올라온 것만 태그별로 묶어서** 메시지로 정리해 줍니다.

**링크 올리는 법**
```
https://youtube.com/shorts/... #요리 #자취
https://www.instagram.com/reel/...
하체 루틴 #운동          ← 링크 바로 다음에 따로 보내도 같은 영상의 태그·메모로 연결
```

**Blueberry가 보내는 메시지 (예시)**
```
🫐 Blueberry 릴스 정리 · 10/02 · 새 영상 3개 (태그 2 · 미분류 1)

#요리 (1)
• [유튜브] 자취생 5분 계란찜 · #자취 — 이하늘, 최유진 <링크>
#운동 (1)
• [인스타] 하체 루틴 — 이하늘 <링크>
미분류 (1)
• [틱톡] 웃겨서 공유 — 박서준 <링크>
```

- **분류는 내가 단 태그로만** 합니다 (AI 없음). 태그가 없으면 "미분류"에 들어갑니다.
- **제목**은 디스코드 미리보기 카드에서 가져옵니다. 인스타는 미리보기가 없는 경우가 많아 메모가 대신 표시됩니다.
- **같은 영상**은 공유 링크 꼬리표(`?si=`, `?igsh=`)와 링크 모양(youtu.be / shorts / watch)이 달라도 하나로 합칩니다.
- **어디까지 정리했는지**는 Blueberry가 마지막으로 보낸 정리 메시지를 기준으로 합니다. 자동 실행이 늦어지거나 하루 빠져도 빠지거나 겹치는 링크가 없습니다.
- 메시지가 길면 디스코드 글자 수 제한(2,000자)에 맞춰 여러 개로 나눠 보냅니다.

직접 실행:
```bash
python -m purchase_collector --mode reels --discord 채널ID          # 화면에만 출력
python -m purchase_collector --mode reels --discord 채널ID --post   # 채널에 보내기
```

### ④ 테스트
```bash
python -m unittest discover -s tests
```
`tests/fixtures`의 대화는 모두 **가상의 샘플**입니다. 디스코드 테스트는 실제 서버 없이 가짜 API 응답으로 돌아갑니다.

## 6. 한계와 다음 단계

- 단축 링크(`coupa.ng`, `naver.me`)는 실제 상품 주소를 열어보지 않기 때문에, 같은 상품의 일반 링크와 중복으로 합쳐지지 않을 수 있습니다.
- 수량은 "3개", "2박스"처럼 숫자+단위 표현만 인식합니다. "두 개"처럼 한글로 쓴 수량은 인식하지 못합니다.
- 상품명과 가격은 쇼핑몰 정책상 자동으로 가져오지 않고, 담당자가 확인해서 입력합니다.
- 디스코드는 서버 별명이 아니라 사용자의 표시 이름을 씁니다.
- 다음 단계: 링크가 올라오면 바로 ✅ 반응, 수량이 없으면 되묻기, 행사별 예산 한도 표시, 품의서 양식으로 내보내기.
